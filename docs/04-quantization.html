Chapter 4

Quantization: the same weights in a quarter of the bits

Pruning chose which weights survive; quantization shrinks how many bits each survivor occupies. The distilled stage-3 checkpoint was benchmarked three ways — fp16, INT8, and NF4 4-bit — same exam, same prompts. The result: 3.79 GB (−72%) at 81/100, with no measurable accuracy cost. This is where the pipeline's memory win actually lands.

Fewer bits per weight

A weight is just a stored number, and the storage format is a dial. fp16 spends 16 bits on each of the 7.24 billion weights; INT8 rounds them to 8-bit integers; NF4 packs them into 4-bit codes. Halve the bits, halve the model:

The two compressed formats are smarter than plain rounding, which is why so little quality is lost. INT8 (bitsandbytes' LLM.int8) keeps the rare outlier channels — the values that would be mangled by rounding — in fp16 on the side. NF4 (NormalFloat4) chooses its 16 levels to match the bell-curve distribution real weights follow, and dequantizes each block back to bf16 just-in-time for the actual math. It is the same format QLoRA used for training in the sibling walkthrough — and the same one the student was distilled in (Chapter 3), so the deployed model is evaluated exactly as it was repaired.

Notice what fp16 says: 13.51 GB — the full dense size. This is Chapter 2's caveat, now measured: 39% of these weights are zeros, and dense storage charges for them anyway. The 3.79 GB NF4 figure doesn't exploit the sparsity either — it's pure bits-per-weight. A 2:4-sparse and 4-bit format would stack the two savings; that remains on this project's to-do list.

The 4-bit model "beat" fp16 by two points. It didn't, really. Two samples on a 100-question exam is inside the noise band from Chapter 1. The honest headline — and it's a good one — is that dropping from 16 bits to 4 cost nothing measurable, while cutting memory 72%. When quality is flat, the cheapest format wins: NF4.

Postscript: the AWQ rematch

The original plan called for AWQ (activation-aware weight quantization — it scales important channels before rounding so they survive it, a spiritual cousin of Wanda's scoring). The package wasn't available in the environment at benchmark time, so the run shipped on bitsandbytes — and a later follow-up closed the gap: the distilled stage-3 model, LoRA merged in, quantized to AWQ W4A16 via llm-compressor.

4-bit formatCorrect / 100Note
NF4 (bitsandbytes)81the incumbent

The two loaders' memory readouts aren't comparable (different backends account differently — the AWQ path even reports a larger footprint than fp16, an accounting artifact, not physics), so the comparison rests on accuracy and ecosystem fit. Verdict, from the report itself: keep NF4 as the default; reach for AWQ only when a serving stack specifically requires that format.
