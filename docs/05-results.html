Chapter 5

The scorecard: 81/100 at 28% of the memory

End to end, the pipeline turned a 13.5 GB fp16 checkpoint scoring 74/100 into a 3.79 GB NF4 artifact scoring 81/100 — with 39% of its weights zeroed and its behavior repaired by its own former self. This chapter tallies the result honestly: every number's provenance, the caveats that survive scrutiny, and what a learner should try next.

Grading against the success criteria

Chapter 1 listed the gates that were set before the experiments. The tally:

  • Accuracy within 1–2% of baseline (the plan's pre-registered wording, which on this 100-question exam means 1–2 points) — passed with room: 81 vs 74. The defensible claim is "no measurable loss" (the +7 is within ±4-point exam noise plus the extra training distillation adds).
  • Memory target — passed: 3.79 GB fits every GPU tier from Chapter 1's chart, with headroom for activations and KV cache.
  • No new unsafe behavior — not actually measured. The exam checks yes/no/maybe accuracy only; hallucination and safety evaluation never ran. An honest scorecard says so.

What ships

The deployment recipe is the distilled stage-3 checkpoint loaded 4-bit — the exact configuration it was repaired and benchmarked in:

# the recommended checkpoint, as benchmarked (81/100 · 3.79 GB)
model = AutoModelForCausalLM.from_pretrained(
    "artifacts/iterative-wanda-2of4-distilled/stage3_add_down_proj",
    quantization_config=BitsAndBytesConfig(
        load_in_4bit=True,
        bnb_4bit_quant_type="nf4",        # Chapter 4's winner
        bnb_4bit_use_double_quant=True,
        bnb_4bit_compute_dtype=torch.bfloat16,
    ),
)

Caveats that survive scrutiny

  • The exam is small. 100 questions puts one standard error at ±4 points. Every conclusion here is directionally solid (the 13-point drop, the 18-point recovery) but single-digit deltas — including the final "+7" — should not be quoted as improvements.
  • Accuracy is the only measured axis. No latency or throughput numbers, no hallucination rate, no safety red-teaming. For a medical model those aren't optional before any real deployment — this artifact is educational.
  • The sparsity is still an IOU. The 2:4 pattern makes hardware speedups and sparse storage possible, but this pipeline never cashed that check; the realized 72% memory cut is all quantization.
  • The alignment footnote. The lifecycle continued after SFT — DPO/GRPO in the sibling medical-llm-RL project — but left held-out accuracy unchanged, so these compression results carry over. If a future alignment run actually moves accuracy, re-running this pipeline becomes a real experiment: does compression preserve the gain?

What to try next

The best exercises this repo supports, in order:

  1. Widen the exam. Score baseline and compressed models on the full labeled PubMedQA set or another medical benchmark. Watching error bars shrink around these conclusions (or break them) is the most instructive follow-up.
  2. Cash the sparsity IOU. Run the stage-3 model through 2:4 sparse kernels and sparse storage, and measure wall-clock latency and real VRAM — turning Chapter 2's paper 8.24 GB into an observed number.
  3. Prune the attention. The original plan reserved attention projections as a cautious follow-up. The iterative harness makes it a one-line stage addition — watch the gates.
  4. Re-match AWQ on equal footing. Chapter 6 serves the AWQ build in vLLM and measures it against fp16; the open piece is putting NF4 and AWQ W4A16 head-to-head in the same stack so their memory and latency are finally comparable, not just accuracy.
  5. Swap the subject. Nothing in the pipeline is medical except the data paths: point the scripts at any finetuned checkpoint with a test set, and the same prune → distill → quantize story replays on your model.

⚠️ The compressed model inherits every limitation of the original — and the whole point of this chapter is that compression was verified on one narrow axis only. It answers medical questions in a convincing register; never use it for real medical decisions. That caveat compresses losslessly.
