Chapter 2

Pruning: deleting 2.8 billion weights on purpose

Pruning bets that a large share of a trained model's weights contribute almost nothing — the hard part is deciding which. This run used Wanda-style scoring (judge each weight by its size times how loud its input is on real medical prompts) with a 2:4 pattern (in every group of four weights, keep the best two), applied to the model's MLP layers in three stages — re-taking the exam after each.

Step 1 — pick a target: the layers that can spare it

A transformer block has two halves: attention (which routes information between tokens) and the MLP, or feed-forward network (which transforms it). The MLPs hold nearly 78% of all weights and are widely observed to be the most redundant part of large models — so this run pruned only the three MLP matrices (up_proj, gate_proj, down_proj) in each of the 32 blocks, and left attention, embeddings, and norms dense.

Step 2 — score every weight: Wanda's insight

The naive rule — keep big weights, delete small ones (magnitude pruning) — misses something: a weight only matters if its input actually fires. Wanda scores each weight as |weight| × average |activation| of its input channel, where the activation statistics come from running 128 real medical prompts through the model and recording, per input channel, how loud it typically is. A big weight attached to a quiet channel is dead weight; a modest weight on a loud channel is load-bearing.

Step 3 — give the sparsity a shape: 2:4

Instead of deleting the globally worst 50%, the run walks each weight matrix in groups of 4 consecutive input weights and keeps the top-2 scores per group. This "2:4 semi-structured" pattern guarantees exactly 50% sparsity in every pruned layer, and it's the specific layout NVIDIA's sparse tensor cores can execute at up to 2× speed — random scattered zeros get no such hardware help. The whole scoring-and-masking step is a few tensor operations, straight from run_iterative_pruning.py:

score = w.abs() * act_mean            # |W| × mean |x|, per input channel
groups = score.view(rows, -1, 4)      # groups of 4 along the input dim
keep = torch.topk(groups, k=2, dim=2).indices
mask.scatter_(2, keep, True)          # mark the top-2 of each group…
w.mul_(mask)                          # …and zero the other two, in place

Note what pruning is not: no training, no gradients, no labels. One pass of calibration statistics, one pass of masking — minutes, not hours.

Three stages, an exam after each

Rather than pruning all MLP matrices at once, the run went iteratively — first every block's up_proj, then adding gate_proj, then down_proj — each stage zeroing exactly half of ~1.88B newly-considered weights, and each followed by the full 100-question exam:

The stage-1 surprise: deleting 940 million weights made the score go up by 3. Don't celebrate — Chapter 1's calibration says ±4 points is one standard error on this exam, and light pruning can also act as mild regularization. The honest reading is "up_proj at 50% sparsity is free", not "pruning improves models". By stage 3 the trend is unambiguous: −13 points. That damage is what Chapter 3 has to repair.

The dense-storage caveat. A zeroed weight still occupies its 2 bytes unless the storage format or the kernels actually skip zeros. Saved to disk the stage-3 checkpoint is as large as the original, and Chapter 4 will measure exactly this: 13.51 GB in fp16 memory despite 39% of weights being zero. The 2:4 pattern makes the savings claimable — with sparse-aware kernels and storage — but in this pipeline the realized memory win comes from quantization. Pruning's contribution here is capacity removed, not bytes saved.
